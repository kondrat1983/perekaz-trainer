# CLAUDE.md — правила проекта «Переказ»

Тренажёр для пересказа украинской литературы (MVP: «Щасливий принц»). Статический сайт на GitHub Pages. Полное ТЗ — в `SPEC.md`.

## Общение

- С владельцем проекта (Кондрат) — по-русски, коротко, на «ты».
- Владелец работает с iPhone: шаги в интерфейсах описываем для телефона и английского интерфейса.
- Вопросы задавай пачками по 3–5, к каждому давай рекомендуемый ответ. Ответы записывай в `docs/DECISIONS.md`.

## Порядок работы

- Продакшн-код не пишем, пока не сделан и не одобрен мокап первого экрана (SPEC.md, раздел 6).
- Сначала читаем SPEC.md целиком. Изменения в спецификации — только по решению владельца, с записью в `docs/DECISIONS.md`.

## Персональные данные

- В репозиторий не кладём имя ребёнка, его фото, возраст, класс, результаты и любые персональные данные.
- В коде, данных и тексте ребёнка называем «Игрок».
- Прогресс хранится только локально (`localStorage` в try/catch). Без аккаунта, без сервера.

## Авторские права

- Не кладём текст и иллюстрации из учебника. Текст сказки пишем сами, короткими пересказами.
- Имена персонажей и предметы берём из оригинала Оскара Вайльда (public domain).
- Картинки — свои SVG (плоские иконки) или свои фото. Для каждого персонажа одна картинка.

## Технические правила

- Статический сайт: HTML, CSS, JS. Без сервера и сборки, если можно.
- HTTPS обязателен (нужен для микрофона). Работа на GitHub Pages.
- Экраны работают в вертикальной и горизонтальной ориентации, от iPhone SE до iPad. Крупные кнопки, один вопрос на экран.
- Все обращения к `localStorage` оборачиваем в try/catch.
- Service worker отдаёт файлы из кэша: при любом изменении картинок, данных, CSS или JS поднимаем `CACHE` в `sw.js`, иначе на телефонах останется старая версия.
- Тесты: нормализатор ответов (таблица ввод → ожидание), Playwright smoke-тест режима «Выбор». Ручная проверка на iPhone Safari.

## Git

- Коммиты делаем на ветке `claude/…` от свежего `main`, не в `main` напрямую.
- Каждое готовое изменение идёт через pull request в `main`. PR создаём сами, отдельная просьба не нужна.
- Перед пушем гоняем `npm test` (юнит-тесты и Playwright).
- PR мёрджим сами, когда CI зелёный и тесты прошли. Владелец разрешил это заранее. После мёрджа коротко сообщаем, что вошло.
- Если PR меняет что-то спорное (дизайн, тексты для ребёнка, удаление данных), сначала спрашиваем владельца.
- Деплой на GitHub Pages идёт только из `main` (workflow `.github/workflows/pages.yml`): среда `github-pages` не принимает другие ветки. После мёрджа проверяем, что деплой прошёл.
- Перед коммитом проверяем, что в diff нет данных ребёнка и текста учебника.
